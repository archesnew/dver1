## 1. Сводная оценка готовности архитектуры

Архитектурная модель данных каталога «Двери №1» прошла четыре последовательные фазы углубленного аудита (V1 → V2 → V3 → V3.1 → V3.2).

В версии V3.2 достигнуто **полное, бесшовное соответствие** между:
1. Физическим DDL-кодом схемы базы данных PostgreSQL (`final-schema-v3.2.md`);
2. Бизнес-логикой комплектации, расчета доборов и опциональности ручек (`configuration-validation.md`);
3. Системой 4 независимых слоев статусов (`status-consistency.md`);
4. Классификатором сервисных услуг (`services-schema-validation.md`);
5. Механизмами защиты неизменяемости истории подтвержденных заказов (`order-immutability-tests.md`).

## 2. Анализ остаточных коммерческих рисков и зона ответственности владельца

Технические риски архитектуры базы данных сведены к нулю за счет ограничений ядра СУБД (CHECK-ограничения, внешние ключи Exclusive Arc, триггеры неизменяемости).

Остаточные риски лежат исключительно в плоскости коммерческих решений владельца бизнеса:

| Остаточный риск | Вероятность | Последствия при отсутствии решения | Рекомендация для владельца |
| :--- | :---: | :--- | :--- |
| **1. Задержка утверждения тарифов на услуги** | Средняя | Невозможность автоматического расчета сметы монтажа и доставки в корзине. | Утвердить тарифную сетку по Казани и Челнам до этапа тестирования оформления заказа. |
| **2. Ручка: умная рекомендация vs пустой выбор** | Низкая | При пустом выборе до 35% клиентов случайно забудут добавить ручку в заказ. | Утвердить рекомендованный вариант А: показ популярной ручки с возможностью отказаться в 1 клик. |
| **3. Регламент обработки 349 групповых фото** | Средняя | Задержка запуска платного трафика из-за неготовности карточек на белом фоне. | Утвердить обработку ТОП-80 ходовых моделей дизайнером, для остальных применить CSS-кадрирование. |
| **4. Срок удержания складской брони** | Низкая | Риск заморозки ходового складского запаса нерешительными клиентами. | Утвердить рекомендованный лимит 72 часа (3 календарных дня) с авто-напоминанием по SMS. |
