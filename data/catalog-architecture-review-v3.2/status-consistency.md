## 1. Разделение и устранение дублирования `is_active` и `is_published`

В типовых CMS часто существует одно поле `is_active`, которое одновременно отвечает и за видимость на сайте, и за возможность редактирования в админ-панели. В каталоге «Двери №1» эти функции **строго разделены**:

| Поле в таблице `products` | Тип данных | Область ответственности | Бизнес-сценарий применения |
| :--- | :---: | :--- | :--- |
| **`is_active`** | `BOOLEAN` | **Внутренний жизненный цикл карточки в ERP / учетной системе.** | `TRUE` — действующая модель, доступна для обработки менеджерами, включена в отгрузочные реестры.<br/>`FALSE` — карточка отправлена в архив (модель снята всеми фабриками навсегда более 12 месяцев назад). |
| **`is_published`** | `BOOLEAN` (DEFAULT `FALSE`) | **Клиентская витрина и поисковая оптимизация (SEO).** | `FALSE` (Безопасный DEFAULT) — новый товар скрыт от витрины до проверки контентом.<br/>`TRUE` — страница открыта по URL (отдает `200 OK`), включена в `sitemap.xml`, доступна поисковикам. |

### Почему они обязаны быть независимыми:
1. **Предварительная подготовка коллекции:**  
   Контент-менеджер заносит новую коллекцию дверей за месяц до старта продаж.  
   `is_active = TRUE` (менеджеры видят товар в админке, связывают погонаж и фурнитуру), но `is_published = FALSE` (покупатели на витрине не видят товар до официального анонса).
2. **Защита поискового трафика (SEO) при отсутствии товара:**  
   Товар временно закончился на складах и у поставщика.  
   Если выключить карточку, поисковые системы выбросят страницу из индекса, и магазин потеряет тысячи переходов из органического поиска.  
   Решение: `is_published = TRUE` (страница открыта, отдает статус 200, сообщает покупателю: *«Временно под заказ / Оставить заявку на уведомление»*), а факт отсутствия отображается через складские слои.

## 2. Разделение статусов ценообразования (`price_status`)

В версии V3.2 статус `price_status` расширен до **4 взаимоисключающих состояний**:

```sql
CONSTRAINT chk_product_price_status CHECK (
    price_status IN ('fixed', 'from', 'quote', 'pending_price')
)
```

| Статус цены | Назначение и критерии | Отображение на витрине | Запрещенные практики |
| :--- | :--- | :--- | :--- |
| **`fixed`** | Стандартная модель с подтвержденной розничной ценой. | *«8 900 ₽ за полотно»* | Нельзя ставить, если цена не проверена по свежему прайс-листу. |
| **`from`** | Базовая витринная цена («от X ₽»), так как итоговая стоимость зависит от габаритов или покрытия. | *«от 11 200 ₽ за комплект»* | Нельзя использовать, если нет базовой подтвержденной цены. |
| **`quote`** | **СТРОГО ИНДИВИДУАЛЬНЫЙ РАСЧЕТ.** Применяется **ИСКЛЮЧИТЕЛЬНО** для заказных нестандартных изделий: полотна 2100–2700 мм, эмаль по RAL, нестандартная фрезеровка. | *«Цена по запросу (расчет технологом)»* | **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** использовать для серийных дверей при отсутствии товара на складе! |
| **`pending_price`** | **НОВЫЙ СТАТУС:** Серийная стандартная модель, для которой розничный прайс находится на обновлении, сверке или загрузке из 1С. | *«Уточняется менеджером»* | Позволяет избежать дезинформации клиентов устаревшими ценами без ложного присвоения статуса индивидуального заказа `quote`. |

## 3. Физический склад vs Цепочка поставок (Исключение `on_order_factory`)

> [!CRITICAL]
> **Архитектурная правка V3.2:**  
> Из таблицы физических складов `stock_items.stock_status` **полностью исключен статус `on_order_factory`**.

### Почему этот статус нарушал архитектуру:
Физический склад в Казани (Сибирский тракт, 59б) или Набережных Челнах (Казанский проспект, 232) — это материальный объект. На нем товар либо физически есть, либо физически забронирован, либо физически отсутствует. Физический склад не может находиться «в процессе заказа на фабрике» — заказ на фабрике размещает отдел закупок у конкретного поставщика.

### Синхронизированная модель:
1. **Складской статус (`stock_items.stock_status`)** отражает только фактический баланс ячейки:
   $$\mathbf{stock\_status} = \begin{cases} 
   \text{'in\_stock'}, & \text{если } (stock\_qty - reserved\_qty) > 0 \\ 
   \text{'reserved'}, & \text{если } stock\_qty > 0 \text{ и } (stock\_qty - reserved\_qty) = 0 \\ 
   \text{'out\_of\_stock'}, & \text{если } stock\_qty = 0 
   \end{cases}$$
2. **Статус поставки (`product_suppliers.supplier_status`)** отражает возможность поставки заводом:
   - `'active'` — складская программа поставщика;
   - `'on_order'` — производство под заказ с фабрики;
   - `'discontinued'` — снято с производства.

## 4. Матрица согласованности и правила формирования витрины

Витринный интерфейс вычисляется динамически на пересечении 4 независимых слоев:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    ЛОГИКА ФОРМИРОВАНИЯ ВИТРИННОГО СТАТУСА                     │
└──────────────────────────────────────┬───────────────────────────────────────┘
                                       │
            ┌──────────────────────────┴──────────────────────────┐
            ▼                                                     ▼
┌───────────────────────────────┐             ┌───────────────────────────────┐
│ Склад города (Казань / Челны) │             │    Поставщики (Дилеры/Завод)  │
├───────────────────────────────┤             ├───────────────────────────────┤
│ stock_status = 'in_stock'     │             │ supplier_status = 'active'    │
│ (Есть на складе в городе)     │             │ (Доступен к заказу)           │
└───────────────┬───────────────┘             └───────────────┬───────────────┘
                │                                             │
                ▼                                             ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ ИТОГ ДЛЯ ПОКУПАТЕЛЯ: «В наличии на складе сегодня (самовывоз / доставка 1-2 дня)»│
└──────────────────────────────────────────────────────────────────────────────┘
```

| Сценарий | `is_published` | `price_status` | Склад Казани | Склад Челнов | Статус у поставщика | Итоговый статус на витрине для клиента |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **Серийная в наличии** | `TRUE` | `fixed` (7 500 ₽) | `in_stock` (10) | `in_stock` (4) | `active` | **«В наличии на складе (доставка 1–2 дня)»** |
| **Нет на складе, есть на заводе** | `TRUE` | `fixed` (7 500 ₽) | `out_of_stock` (0) | `out_of_stock` (0) | `on_order` | **«Под заказ с фабрики (срок уточняется менеджером)»** |
| **Новинка ожидает прайса** | `TRUE` | `pending_price` | `out_of_stock` (0) | `out_of_stock` (0) | `active` | **«Новинка (цена уточняется менеджером)»** |
| **Индивидуальный спецзаказ** | `TRUE` | `quote` | `out_of_stock` (0) | `out_of_stock` (0) | `on_order` | **«Индивидуальный расчет под проем клиента»** |
| **Снято с производства** | `TRUE` | `fixed` (архив) | `out_of_stock` (0) | `out_of_stock` (0) | `discontinued` | **«Модель снята с производства (Показать аналоги)»** |

## 5. SQL-тесты согласованности складских полей и триггера

Автоматический триггер `sync_stock_status()` в схеме V3.2 гарантирует математическую целостность складских статусов:

```sql
-- ТЕСТ 1: Приход товара на склад (stock_qty = 10, reserved_qty = 0)
INSERT INTO stock_items (warehouse_id, variant_id, stock_qty, reserved_qty)
VALUES ('kazan_central', 'VAR-ESC-2000-800-WHT', 10, 0);

-- Проверка: stock_status обязан автоматически стать 'in_stock', available_qty = 10
SELECT stock_qty, reserved_qty, available_qty, stock_status FROM stock_items WHERE variant_id = 'VAR-ESC-2000-800-WHT';
-- Результат: (10, 0, 10, 'in_stock') -> УСПЕШНО

-- ТЕСТ 2: Бронирование всех 10 единиц (reserved_qty = 10)
UPDATE stock_items SET reserved_qty = 10 WHERE variant_id = 'VAR-ESC-2000-800-WHT';

-- Проверка: stock_status обязан автоматически переключиться в 'reserved', available_qty = 0
SELECT stock_qty, reserved_qty, available_qty, stock_status FROM stock_items WHERE variant_id = 'VAR-ESC-2000-800-WHT';
-- Результат: (10, 10, 0, 'reserved') -> УСПЕШНО

-- ТЕСТ 3: Отгрузка всех единиц (stock_qty = 0, reserved_qty = 0)
UPDATE stock_items SET stock_qty = 0, reserved_qty = 0 WHERE variant_id = 'VAR-ESC-2000-800-WHT';

-- Проверка: stock_status обязан стать 'out_of_stock'
SELECT stock_qty, reserved_qty, available_qty, stock_status FROM stock_items WHERE variant_id = 'VAR-ESC-2000-800-WHT';
-- Результат: (0, 0, 0, 'out_of_stock') -> УСПЕШНО
```
