### 1.2. Реализовано, но ожидает промышленной эксплуатации (Production Hardening)
- **Email-уведомления сотрудникам**: интерфейс отправки служебных писем заложен в коде, требует настройки корпоративного SMTP-сервера (`SMTP_HOST`, `SMTP_PORT`).
- **Автоматический парсинг входящих банковских платежек 1С**: в текущей версии оплата подтверждается менеджером вручную через статус «Подтверждена / Оплачена».

---

### 1.3. Требует внешнего подключения (External Integrations)
- **Telegram Bot Webhook**: модуль отправки уведомлений (`dispatchTelegramNotification`) реализован в `server.js`. Для отправки в реальный чат требуется указать валидные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в переменных окружения. При отсутствии токенов уведомления безопасно логируются в `data/orders/telegram.log` без прерывания оформления заявки.
- **SMS-шлюз (SMS.RU / SMSC.RU)**: эмулятор кодов подтверждения телефона работает в режиме `development`. Для отправки реальных SMS на телефоны покупателей требуется передать рабочий `SMS_API_KEY`.

---

### 1.4. Не реализовано (В соответствии с регламентом)
- **Публичная регистрация сотрудников**: строго запрещена правилами безопасности проекта. Добавление персонала выполняется исключительно Владельцем из защищенного раздела «Сотрудники».
- **Автоматическое списание складских остатков без подтверждения менеджером**: запрещено регламентом. Наличие подтверждает менеджер после физической инспекции ячейки хранения.
- **Процентные надбавки к ценам под заказ**: строго запрещены формулой `Розница = Закупка + 10 000 ₽`.

## 2. СЕРВЕРНЫЕ API ЭНДПОИНТЫ (`server.js` + `admin-backend.js`)

Все административные маршруты защищены Bearer-токенами с валидацией ролей на стороне сервера:

```
POST   /api/admin/auth/login          — Вход в систему, проверка пароля PBKDF2, выдача токена
GET    /api/admin/auth/me             — Проверка текущей активной сессии
POST   /api/admin/auth/logout         — Отзыв токена и завершение сессии
GET    /api/admin/dashboard           — Сводные KPI, внимание, последние действия
GET    /api/admin/orders              — Реестр заказов с фильтрами, сортировкой и пагинацией
GET    /api/admin/orders/:id          — Детальная информация по конкретному заказу
PUT    /api/admin/orders/:id/status   — Изменение статуса заказа с фиксацией в аудите
PUT    /api/admin/orders/:id/details  — Назначение менеджера, согласованная сумма, заметки
GET    /api/admin/catalog             — Товары каталога (697 позиций) с фильтрацией
GET    /api/admin/catalog/:id         — Карточка отдельного товара
PUT    /api/admin/catalog/:id         — Сохранение изменений товара и цен
GET    /api/admin/inventory           — Складские остатки Казани и Челнов
POST   /api/admin/inventory/adjust    — Ручная корректировка остатка с указанием причины
POST   /api/admin/inventory/transfer  — Межскладское перемещение с проверкой доступности
GET    /api/admin/customers           — Клиентская база и аналитика покупок
POST   /api/admin/customers/note      — Добавление служебной заметки о клиенте
GET    /api/admin/services            — Тарифы и правила монтажных работ
GET    /api/admin/staff               — Список сотрудников (только для роли owner)
GET    /api/admin/audit               — Журнал неизменяемого аудита действий
GET    /api/admin/backups             — Реестр резервных копий (только для роли owner)
POST   /api/admin/backups/create      — Создание моментального снимка базы данных
POST   /api/admin/backups/restore     — Восстановление базы данных из бэкапа
```

## 3. ХРАНЕНИЕ ДАННЫХ В ПРОЕКТЕ

Данные хранятся изолированно в директории `data/` с атомарной записью во временные файлы во избежание повреждения данных при конкурентных запросах:

1. `data/orders/orders.json` — реестр оформленных покупателями заказов со спецификацией полотен, фурнитуры и контактов.
2. `data/admin-users.json` — хэшированные учетные записи персонала (логин, соль, PBKDF2 хэш, роль, статус).
3. `data/catalog-output/products.json` и `products-data.js` — авторитетная база товаров (697 моделей).
4. `data/inventory.json` — складские остатки по складам Казани и Набережных Челнов.
5. `data/customers.json` — база уникальных покупателей, синхронизируемая с заказами.
6. `data/services.json` — официальный прейскурант монтажной службы.
7. `data/pricing-history.json` — история переоценки и примененных прейскурантов.
8. `data/audit-log.json` — лог безопасности и системных изменений.
9. `data/backups/` — архив моментальных снимков состояния системы.
